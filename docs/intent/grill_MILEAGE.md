# Grill Me: MILEAGE

Модель: GLM 5.3. Агент: code. Интервью завершено: 6 из 6 вопросов.

## 1. Граница порога

**Вопрос.** С какой стороны правила находится ровно 400 000 км?

**Ответ.** 400 000 км допустимо: решение определяется LTV. `review` начинается строго с 400 001 км.

## 2. Пробег не указан

**Вопрос.** Меняем ли существующее поведение для отсутствующего `mileage`?

**Ответ.** Нет. Отсутствующий пробег остаётся ошибкой валидации, решение не рассчитывается; контракт входных данных не меняем.

## 3. Приоритет над reject

**Вопрос.** Должен ли пробег выше 400 000 км понижать `reject` до `review`?

**Ответ.** Нет. `reject` доминирует; пробег выше 400 000 км понижает только потенциальный `approve` до `review`.

## 4. Причина review в API

**Вопрос.** Нужен ли в API признак, что `review` вызван именно пробегом?

**Ответ.** Нет. `review` по пробегу неотличим от `review` по LTV: новых полей, причин и флагов не добавляем.

## 5. Не входит в задачу

**Вопрос.** Подтверждаем ли предложенный список вне scope?

**Ответ.** Да. Не меняем валидационный потолок 500 000 км, LTV-границы, LOAN-12, БД и сиды, фронтенд, формат API. Для правила достаточно unit-тестов.

## 6. Итоговая таблица

**Вопрос.** Подтверждаем ли итоговую таблицу решений?

**Ответ.** Да.

| Пробег | LTV < 60.0 | LTV 60.0–85.0 | LTV > 85.0 |
|---|---|---|---|
| ≤ 400 000 | approve | review | reject |
| 400 001–500 000 | review | review | reject |
| отсутствует / вне 0…500 000 | ValidationException | ValidationException | ValidationException |
